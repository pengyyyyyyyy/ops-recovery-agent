# 设计决策

## 模型与执行器分离

诊断与复核使用项目实现的显式 Loop，并复用 smolagents 模型和工具接口。确定性调度器负责状态、schema、执行权限、预算和修复验证。模型接口、服务商和密钥由运行环境配置。

## 调查工具只读

MCP 仅暴露受限的日志、指标、服务清单与运行手册查询。Agent 没有 shell、通用文件读取或审批能力。写操作由白名单执行器在匹配的人工审批下执行。

## 单机持久化

SQLite 提供检查点、顺序事件、运行租约和费用账本，简化单机部署与跨 CLI 进程恢复。该设计不提供多机协调或任意外部系统的 exactly-once 保证。

## 可复现的故障实验

实验环境使用独立业务进程和监督进程，复现进程崩溃、HTTP 慢依赖与 SQLite 锁竞争。修复结果通过实际业务请求验证，而非由模型自行判定。

## 两条评测轨道

本地实验评价诊断与实际修复；公开静态数据只评价诊断。诊断汇总采用本地 60%、公开 40% 的项目协议，同时始终保留分项结果。离线规则模型和真实模型结果分别记录。

## 复核的成本与边界

复核 Agent 使用隔离上下文，并实际取回引用证据；最多触发一次返工。同模型的相关错误仍可能存在，是否采用复核应根据准确率、调用次数和失败模式共同判断。

## 与上游的职责边界

smolagents 提供 Model、Tool 和工具 schema。MCP SDK 提供协议基础。本项目实现 Loop、可靠执行、审批与恢复、双角色编排、故障实验、匿名数据适配和评测报告。
