# 评测协议与结果记录

## 预先确定的协议

- 框架：smolagents 1.26.x；精确依赖见 requirements.lock.txt。
- 变体：baseline = 单 Agent / 工具只尝试一次；reliable = 单 Agent / 只读有限重试；dual = 双 Agent / 只读有限重试。
- 各变体使用相同模型、工具、预算和任务；每次运行的首次 query_logs 注入一次传输超时。模型可自主纠正工具失败，baseline 并非禁止模型重试。
- 本地应用故障为独立的进程崩溃、慢依赖和数据库锁竞争；与工具传输故障分开。
- 本地修复在测试策略批准后执行，故意丢弃首次成功修复的响应，要求查询幂等结果后恢复。
- 公开基准为 RCAEval RE2-OB，3 个开发组 + 12 个测试组；按根因服务与故障类型成组，固定 seed=20261118，每组选一个重复样本。
- 开发期检查过的 checkoutservice/cpu 组永远属于开发集。初轮冻结协议后未用测试成绩修改当轮提示词；后续使用过的案例一律标为历史回归集，不再宣称未见测试集。
- 指标来自注入器真值或公开标签、实际 HTTP 响应、工具事件与模型 usage；不以 LLM 自称成功计分。
- 公开数据用已知事件时间前后 300 秒的指标中位数/MAD 和去重错误日志。事件时间作为告警输入，这是已知事件时间的 RCA，不是异常发现任务。
- 未导入原始分布式 traces。本版本不宣称复现完整 RCAEval 官方算法排行榜。

## 指标含义

`service_ac_at_1`：预测根因服务与答案精确相等的比例；`accepted_correct_rate`：被系统接受且服务正确的比例。另列错误、复核拒绝、调用次数、耗时。

本地 `verified_repair_rate` 要求最后 3 次 checkout HTTP 均为 200；`unknown_response_recovered` 记录丢失响应后的对账恢复；`duplicate_repair_events` 根据监督进程事件计数。

总诊断分仅在同时有两条轨道时计算：`0.6 × local_AC@1 + 0.4 × public_AC@1`。它是项目预定的汇总，不是通用研究指标。修复分数保持独立。

每组提供 Wilson 运行级区间用于描述不确定性，但同一案例的重复结果相关，不能把该区间当作严格独立样本推断。公开测试只有 12 个故障组，应明确样本量，不报告“生产准确率”。

## 已观察到的开发失败

开发验证中曾观察到模型输出 13 条引用，违反最多 12 条的 schema 而失败。该用例用于修复与回归，不作为正式测试成绩。

修复为在 Agent Loop 内校验最终输出，并把校验错误反馈给模型；不通过放宽 schema 隐藏问题。测试覆盖过多引用和不存在的引用。

离线规则模型曾在当前 12 个公开组中定位全部根因服务。这说明这个小样本对指标变化基线较容易，不能由此宣称多 Agent 提高了推理能力。应以真实模型消融结果判断复核的收益与成本，并考虑后续增加不同系统、代码级故障和更困难的根因传播案例。

## 实测结果文件

正式运行后，脱敏的协议、逐运行结果和汇总会归档在 `artifacts/evaluation/`。完整本机 trace 与 HTML 在被 Git 忽略的 `reports/`，可按需要单独审查后分享。

查看每份实验的 protocol.json 可检查模式、模型、提示词摘要、公开数据版本、变体与审批策略。离线结果必须显式标为工程验证，不和 online 成绩混算。

### 从失败 trace 得出的结论

1. `test-004` 真值为 productcatalogservice，多个变体归因到 recommendationservice。日志与延迟展示了下游传播症状，模型没有可靠区分起因与症状。现有统计规则基线反而能命中该样本，不应宣称 LLM 超越它。
2. baseline 的 4 次结构化错误中，末尾自由文本实际上提到了正确服务；但 Loop 达到步数上限后 smolagents 返回了自然语言 fallback，外层 JSON/schema 校验拒绝。有效诊断提升主要是工程完成率收益，不是语义根因判断提升。
3. dual 的 2 次结构化错误发生在复核阶段的自由文本 fallback。额外角色增加了输出协议边界和消耗；复核也接受过错误的下游归因。所有变体最终复核拒绝率为零，不能当作复核有效的证据。
4. 所有无合法结构化结果的会话均停在 failed，没有进入修复执行。新增确定性回归用例检查这一失效边界。

当轮结果未筛选重跑。后续 Loop 改进建立了新的回归迭代，保留完整失败轮次；已经使用过的案例不能证明未见故障的泛化能力。

归档目录包含协议、90 行原始结果、全部失败分类、数据哈希清单、成功恢复及失败案例的代表 HTML trace。可通过 scripts/archive_evaluation.py 从三个完整实验目录重新生成。

## 显式 Loop 回归迭代（2026-11-23）

0.2.0 的完整 60 次回归暴露工具压缩丢失数值和最终提交耗尽步骤的问题。0.2.1 保留异常分数、指标中位数和证据 ID，提高单次工具结果预算至 16,000 B，在剩余步骤提示后以结构化 final_answer 收尾，复核须实际取回其引用证据。步骤上限保持诊断 8、复核 5。

修改前后各运行全部 3 类本地故障与 12 个公开组、两个变体、两次重复。数据 revision、划分与评分一致，源码及提示词摘要分别记录。由于案例此前用于诊断缺陷，本次仅证明历史回归完成情况，不能继续称为未见测试集。线上模型别名和随机性也可能影响结果。

| 轮次 | reliable：公开 / 本地修复 / 加权 | dual：公开 / 本地修复 / 加权 |
|---|---|---|
| 修复前 | 5/24 · 6/6 · 68.33% | 3/24 · 1/6 · 15.00% |
| 修复后 | 24/24 · 6/6 · 100% | 24/24 · 6/6 · 100% |

修复前 500 次请求估算 3.573386 元；修复后 488 次请求估算 3.778614 元。双角色未体现准确率收益，公开案例平均 9.75 次模型调用，单角色为 6.54 次。12 次修复都对成功后丢响应完成对账，重复动作 0。

[完整归档](../artifacts/evaluation/2026-11-23/README.md)提供两轮全部 120 次运行的 JSON/HTML trace、逐运行评分、失败分类和 SHA-256 清单。云端试点、并发、skill 和上下文测试作为独立证据轨道；它们不是这一 60/40 分数的组成部分。
